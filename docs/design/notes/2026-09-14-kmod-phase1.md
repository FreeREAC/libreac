# Kernel-module backend, phase 1 — what landed, and one divergence to settle

- **Governs nothing.** A lane note under
  [`../specs/2026-09-13-reac-kernel-module-backend.md`](../specs/2026-09-13-reac-kernel-module-backend.md),
  which is the source of truth. Where this note and that spec disagree, the spec wins.
- **Operator ruling, 2026-09-14:** "go for it and we'll run comparative tests."

## The divergence, first, because it changes what was built

The lane brief asked for the module to carry "the protocol bytes from libreac's
kernel-portable core, never a second copy — the draft says the core is
kernel-portable by construction: prove it by compiling that core in the kernel
build with the draft's shims."

**The draft says the opposite, in its own words, and it was followed.** §0: the
kernel is GPL-2.0-only, "or-later" reaches forward and never back, so libreac
(GPL-3.0-or-later) *can never be linked into a module* — and the consequence is
named as architectural: "**the module never parses a REAC frame**, and that is
what keeps it small." §8 makes it mechanical: "no libreac symbol undefined" is
"the firewall, never relaxed for convenience." There are no shims in the draft
and no kernel-portable core in it.

So the module contains no REAC protocol: every frame is composed in userspace
with libreac and handed down as bytes. There is no second copy of the protocol,
which is what the brief's requirement was protecting — it is achieved by the
frames crossing a boundary rather than by the code crossing a licence.

This is the whole of the divergence, it is recorded rather than buried, and if
the operator intends the other design it is a licence decision (relicensing
libreac's core, or splitting a GPL-2 core out of it), not a build question.

## What landed here

- **`tools/pace_hist.c`** — the inter-frame interval distribution per talker from
  a mirror capture: mean/min/max/sd, p50/p90/p99/p99.9, and how many intervals
  ran long by 1.5x/2x/4x the nominal or short by half. `--self-test` is its own
  control — a perfect grid must be silent and three injected 1 ms stalls must all
  be found, because an instrument not shown to detect a presence cannot testify
  about an absence, and "the kernel arm had no late slots" is an absence claim.
- **`tools/pace-compare.sh`** — one table, both arms: wire, the arm's own
  `reac-health:` line, and CPU read twice (the kernel arm's cadence is an hrtimer
  callback and appears in no process's counters; a process-only reading would
  hand it a free win the size of the comparison). It never restarts the daemon.
- **`tools/conformance-pace-harness.sh`** — in `make conformance`. It requires the
  instrument to SEPARATE a clean 8000 fps grid from the userspace pacer's own
  measured miss distribution (250/500/2000 µs, from `reac_pacer.h`'s soak) on
  late/s, p99.9 and max while both carry the same packet rate. Without this, a
  harness that cannot resolve the difference would print a tidy table reading
  "no difference" and waste the comparative test day.

## Two bounds the table must be read with

- **Resolution is 1 µs.** Classic pcap carries microseconds, so at 125 µs nominal
  this resolves ~0.8% of a period and nothing finer. It is pointed at a signal
  far above that — the userspace pacer's measured single-miss debt is 250 µs at
  p50 and 2000 µs at worst — but a sub-microsecond claim may not be made from it.
  A nanosecond-magic pcap is refused by name rather than read 1000x wrong.
- **`reac_rate_snap` has no floor.** It is a nearest-of-three and answers
  44100 Hz for 196 pps. `pace_hist` prints the snapped rate only when the
  observed packet rate is within 10% of a legal pace; outside that it says
  `rate_hz=n/a reason=pps_is_not_a_legal_pace`. A rate printed for a partial
  capture is exactly the false signal this whole instrument exists to avoid.

## The module, and where its evidence lives

The kernel side is `reac-kmod`, branch `lane/kmod-phase1`: `/dev/reacN`, the
ten-ioctl boundary, three mapped rings, the hrtimer cadence, the RX copy, the
`reac` group and udev rule, and the SRPM. **It compiles and has never been
loaded.** Its owed list — every row that cannot be proven without loading it,
with the exact commands in order and the proof that ends each — is in that
repository's `docs/verification.md`, not here, because that is where whoever
runs it will be standing.

The one thing that cannot be predicted from a compile: the timer callback runs in
hardirq context and hands the skb at the driver under `HARD_TX_LOCK`, bypassing
the qdisc, because `__dev_queue_xmit`'s `rcu_read_lock_bh()` is illegal there.
Whether the rig's NIC driver takes that handoff is the first question of the
comparative test day, and `dmesg` under `CONFIG_PROVE_LOCKING` is how it is
answered — before any frame count is believed.
